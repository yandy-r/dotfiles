# dotfiles — Agent Rules

The canonical agent rules for this repository live in [`CLAUDE.md`](CLAUDE.md).

This file exists so agent-runtime tools that default to `AGENTS.md` (Cursor, Windsurf,
OpenAI Codex, etc.) pick up the same rules without duplicating prose.

## Agent-runtime notes

- Cursor: also reads `.cursor/rules/project.mdc` (same content, MDC-formatted).
- Vendor-neutral AI tools: also read `.ai/rules/project.md` (same key points).
- When an MCP server is available for the task, prefer it; read each tool's schema first.
- For deep analysis of this repository, start with `CLAUDE.md` and the stack overview.
- This is now a **Go + shell mono-repo**: a `dotf` provisioning CLI (`cmd/dotf` +
  `internal/*`, Go 1.26) is grown alongside the default shell system. `bin/style.sh`
  lints Go + shell + Python + Markdown (`--go` scopes Go; `--docs` scopes Markdown and
  is opt-in); CI runs `.github/workflows/go.yml`.
  See `CLAUDE.md` → Stack Overview for the canonical detail.
- Symlinks are provisioned natively by `dotf link` (`internal/symlink`); the Ansible
  `playbooks/symlinks.yml` is historical-rollback-only. `dotf sysconfig`
  (`internal/sysconfig`) owns per-OS system config (hostname/timezone/locale/shell/firewall).
  As of Phase 7, `bootstrap.sh` is a POSIX download-and-exec shim (~608 lines) that downloads the
  checksum-verified `dotf` binary from GitHub Releases and execs `dotf apply` (the bash provisioning
  path is retired as the entry point; the `bin/install-*.sh` installers are retained and driven by
  the manifest via the `custom-script` backend). See `CLAUDE.md` → Symlink Management / Stack
  Overview for the canonical detail.

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

When the user types `/graphify`, use the installed graphify skill or instructions before doing anything else.

Rules:

- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- Dirty graphify-out/ files are expected after hooks or incremental updates; dirty graph files are not a reason to skip graphify. Only skip graphify if the task is about stale or incorrect graph output, or the user explicitly says not to use it.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).

## Branching & releases

[`RELEASING.md`](RELEASING.md) is the source of truth for branches and releases. Branch
off `main` and PR back into it; every release is tagged from `main`. Never merge one
long-lived branch into another to sync it.
