# v0.3.0

First stable release of `dotf` — the native Go provisioning CLI for this dotfiles
repository. It provisions a complete development environment through one
checksum-verified `bootstrap.sh` → `dotf apply` path across macOS, Arch, Debian,
Ubuntu, Fedora, openSUSE, and WSL.

## Highlights

- **First stable release.** The beta provisioning pipeline is promoted to stable after
  adding package lifecycle management, diagnostics, self-update, user overlays,
  reproducible release locking, and cross-platform system configuration.
- **Fedora and Fedora Asahi parity.** Fedora, Fedora Asahi Remix, RHEL, CentOS, Rocky,
  and AlmaLinux use the same manifest and apply phases as every other supported host.
  DNF5, locale provisioning, firewalld, shell selection, and SELinux diagnostics are
  handled natively.
- **Governed package lifecycle.** `dotf install`, `status`, `diff`, `plan`, `doctor`,
  `lock`, `verify`, and `self-update` provide explicit install, update, remove,
  diagnostics, drift, and reproducibility workflows. Package classes distinguish
  pinned, rolling, and externally managed software.
- **KDE Plasma 6 management.** `dotf plasma` captures, compares, and applies curated
  KDE settings while stripping host-local values such as wallpaper history and default
  browser associations.
- **Safe symlink and system configuration.** Directory destinations are backed up
  before replacement. Hostname, timezone, locale, shell, firewall, and optional SSH
  server configuration use typed, platform-specific implementations.
- **Broader CLI catalog.** The manifest now includes Herdr and npm-managed cloud CLIs
  for Vercel, Railway, Stripe, Neon, and OpenCode 2. The npm toolchain path works across
  supported operating systems and refreshes mise shims after installation.
- **Native backend expansion.** GitHub release auto-detection, checksums, package
  probes, OS gates, `provides_any`, git-clone activation, fonts, APT/DNF repositories,
  and XDG user overlays reduce reliance on custom installer scripts.
- **Shell performance and portability.** Shared Linux modules load correctly for each
  distro family, completion work is lazy, and zsh startup dropped from roughly five
  seconds to about 1.2 seconds.

## Notable behavior changes

- `--hyprland` is the primary flag for the opt-in Hyprland/wlroots desktop set.
  `--linux-desktop` remains as a compatibility alias.
- `dotf link --backup` backs up populated directory destinations instead of deleting
  them recursively.
- `dotf plasma` treats default-browser associations as host-local and does not manage
  them.
- Homebrew is declined on aarch64 Linux, where upstream does not publish supported
  bottles.
- OpenCode 2 installs as the separate `opencode2` binary from `@opencode/cli`, allowing
  it to coexist with the existing `opencode-ai` CLI.

## Install

Release workflows publish static binaries for **Linux and macOS** on **amd64 and
arm64**, plus `checksums.txt`. Windows is supported through WSL, not a native binary.

```bash
git clone https://github.com/yandy-r/dotfiles.git ~/.config/dotfiles
cd ~/.config/dotfiles
./bootstrap.sh
```

Install optional cloud and AI CLIs with:

```bash
dotf apply --intent cloud --intent ai
```
