# v0.2.1-beta

Maintenance release of `dotf` — the native Go provisioning CLI for this dotfiles
repository. There are **no user-facing behavior changes to the `dotf` binary** since
`v0.2.0-beta`; this release fixes the project's CI so it runs cleanly on **both**
GitHub Actions and the self-hosted **Forgejo** mirror (origin), and refreshes the
internal roadmap/research docs.

> **Beta scope.** Unchanged from v0.2.0-beta — `dotf` provisions the real
> daily-driver toolset across the full pass (sysconfig → packages → symlinks →
> firewall). Pin to a tag rather than tracking `latest` if you need stability.

## Highlights

- **Forgejo-compatible CI.** The self-hosted Forgejo runner resolves unqualified
  action references against its `DEFAULT_ACTIONS_URL` (`data.forgejo.org`), which
  mirrors only `actions/*` and `forgejo/*` — so third-party actions 404 on Forgejo.
  Two fixes make CI green on both forges:
  - The GitHub-targeted **release** workflow now skips cleanly on the Forgejo runner
    (the release is published to GitHub Releases by design), guarded by
    `github.server_url`.
  - The **Go** workflow installs `golangci-lint` via the pinned upstream script
    instead of `golangci/golangci-lint-action`, so the lint step is byte-identical
    on GitHub and Forgejo.
- **Docs refresh.** Reframed the dotf script-retirement metric, fixed roadmap/README
  drift, and added strategic research on future `dotf` CLI enhancements.

## Maintenance

- `ci`: skip the GitHub-targeted release job on the self-hosted Forgejo runner.
- `ci`: install golangci-lint via a pinned script so Go CI resolves on Forgejo.

## Install

The release workflow (GoReleaser) publishes static binaries for **linux, darwin, and
windows** on **amd64 and arm64**, plus `checksums.txt`. The bootstrap shim resolves
`/releases/latest/download/dotf_<os>_<arch>.tar.gz` automatically:

```bash
git clone https://github.com/yandy-r/dotfiles.git ~/.config/dotfiles
cd ~/.config/dotfiles
./bootstrap.sh
```
