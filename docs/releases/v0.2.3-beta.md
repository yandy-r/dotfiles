# v0.2.3-beta

Maintenance release of `dotf` — the native Go provisioning CLI for this dotfiles
repository. There are **no user-facing behavior changes to the `dotf` binary** since
`v0.2.2-beta`. This release fixes the Forgejo release CI so the self-hosted origin
publishes its releases automatically, end-to-end.

> **Beta scope.** Unchanged from v0.2.2-beta — `dotf` provisions the real
> daily-driver toolset across the full pass (sysconfig → packages → symlinks →
> firewall). Pin to a tag rather than tracking `latest` if you need stability.

## Highlights

- **Forgejo release CI fixed.** Forgejo's runner auto-injects `GITHUB_TOKEN`, and
  GoReleaser aborts with "multiple tokens found" when both `GITHUB_TOKEN` and
  `GITEA_TOKEN` are set. The Forgejo release workflow now unsets `GITHUB_TOKEN` so
  the gitea publisher uses `GITEA_TOKEN` only. This is the first tag to publish a
  Forgejo release fully through CI (the v0.2.2-beta Forgejo release was cut manually
  while diagnosing this collision).

## Maintenance

- `ci`: unset `GITHUB_TOKEN` in the Forgejo release so GoReleaser uses `GITEA_TOKEN`.

## Install

The GitHub release workflow (GoReleaser) publishes static binaries for **linux,
darwin, and windows** on **amd64 and arm64**, plus `checksums.txt`. The bootstrap
shim resolves `/releases/latest/download/dotf_<os>_<arch>.tar.gz` automatically:

```bash
git clone https://github.com/yandy-r/dotfiles.git ~/.config/dotfiles
cd ~/.config/dotfiles
./bootstrap.sh
```
