# v0.3.0-beta

Feature release of `dotf` — the native Go provisioning CLI for this dotfiles
repository. This release brings **Fedora** — including Fedora Asahi Remix on Apple
Silicon — to first-class parity with the existing macOS, Arch and Debian support,
through the identical `bootstrap.sh` → `dotf apply` pipeline. There is no bespoke
Fedora side path: the same detector, the same manifest, the same phases.

> **Beta scope.** Unchanged from v0.2.3-beta — `dotf` provisions the real
> daily-driver toolset across the full pass (sysconfig → packages → symlinks →
> firewall). Pin to a tag rather than tracking `latest` if you need stability.

## Highlights

- **Fedora / RedHat family support.** Detection now covers `fedora`,
  `fedora-asahi-remix`, `asahi-fedora-remix`, `rhel`, `centos`, `rocky` and
  `almalinux`, all mapping onto the RedHat family. The `pkg` backend's `dnf` argv are
  dnf5-compatible. Sysconfig grew the Fedora domains it was missing: locale installs
  `glibc-langpack-<lang>` instead of downgrading `LANG`, firewalld is installed when
  absent, `chsh` is guarded with `LookPath` and falls back to `usermod -s`, and
  `dotf doctor` reports the SELinux mode.
- **Binary download fixed for prerelease-only origins.** `bootstrap.sh` now tries the
  tag-pinned `releases/download/<tag>/<asset>` URL it has just resolved before giving
  up. The dominant cause was `.goreleaser.yml`'s `prerelease: auto` combined with
  `-beta` tags: GitHub's `/releases/latest` excludes prereleases, so
  `/releases/latest/download` 404s — on a **public** repository too. This was never a
  repository-visibility problem.
- **Shell configuration now actually loads on every distro.** The per-OS module
  loaders in `common/{aliases,exports,functions}.sh` dispatched on
  `common/$DOTFILES_OS/…`, but `DOTFILES_OS` holds a distro token (`debian`,
  `redhat`, `arch`, `suse`) and never `linux` — a directory that exists for no named
  distro family. Roughly 495 lines of `common/linux/aliases.sh` were therefore dead on
  Fedora, Debian, Arch **and** openSUSE. `os_module_dirs()` in `common/platform.sh` is
  now the single source of truth for a family-then-overlay search path, and the
  regressions that go live with it were fixed in the same change: the dnf and yum
  `history` aliases no longer shadow the shell builtin (they are `pkghistory`), the
  RedHat and openSUSE firewall aliases route to firewalld, the Plasma probe looks for
  `systemsettings` rather than a hardcoded Plasma 5 binary name, and `locale_exists`
  folds the codeset separator so `de_DE.UTF-8` matches glibc's `de_DE.utf8` spelling.
- **Symlink backup safety.** `dotf link --backup` now backs up **directory**
  destinations — `~/.config/nvim`, `wezterm`, `ghostty`, `mise`, `alacritty`,
  `~/.bin` and `~/.config/direnv` — before replacing them. Previously these were
  removed recursively even with `--backup` passed, which was a live data-loss risk on
  a populated daily driver. See _Breaking / behaviour changes_ below.
- **Facet rename.** `--hyprland` is the primary flag for the opt-in Hyprland/wlroots
  desktop set; facets are named by capability rather than by distro.
  `--linux-desktop` and `LINUX_DESKTOP` remain as back-compat aliases. Do not pass it
  on a KDE host.
- **Package manifest.** The fictional `dnf` names for `lazygit` and `yazi` are gone —
  Fedora ships neither RPM in any release or updates branch — replaced by
  `os = "redhat"` github-release siblings (`lazygit-bin`, `yazi-bin`). `lutris` gains
  a Fedora `pkg` sibling (`lutris-pkg`), and `docker-ce` installs on Fedora via the
  vendor `.repo` through the new family-dispatching `repo` backend, which carries
  `apt_repo` and `dnf_repo` sub-tables behind one backend name.
- **Nerd Fonts** now install through a native `font` backend on every platform:
  distro packages where they exist (`ttf-*-nerd` on Arch, casks on Homebrew) and the
  upstream `ryanoasis/nerd-fonts` release archive everywhere else. Previously fonts
  were reachable only through an Arch-only script that the manifest referenced
  nowhere.

## Breaking / behaviour changes

- **Directory destinations are now backed up.** `dotf link --backup` no longer
  recursively removes a populated config directory without saving it first. This is
  strictly safer, but backup directories will grow — the seven directory entries above
  are copied on every run that replaces them.
- **`--linux-desktop` is deprecated** in favour of `--hyprland`. The old flag and its
  `LINUX_DESKTOP` environment twin still work and still select the same set.
- **`dotf plasma` no longer manages the default browser.** `text/html` and the
  `about`, `http`, `https` and `unknown` URL-scheme handlers are now stripped as
  host-local on **every** platform, Arch included: the previously pinned
  `google-chrome.desktop` has no aarch64 Linux build, so exporting it made the
  snapshot unusable on the target device. The AI-app scheme handlers stay managed.
- **Homebrew is declined on aarch64 Linux.** Passing `--homebrew=true` on that host
  now prints an explicit stderr note and continues with the native package manager;
  Homebrew publishes no aarch64-Linux bottles and its installer refuses there. On the
  same host the package-manager detector demotes an incidental Linuxbrew below the
  native manager. An `x86_64` Linux host passing `--homebrew=true` is unaffected.

## Install

The GitHub release workflow (GoReleaser) publishes static binaries for **linux,
darwin, and windows** on **amd64 and arm64**, plus `checksums.txt`. The bootstrap
shim resolves `/releases/latest/download/dotf_<os>_<arch>.tar.gz` automatically, then
falls back to the tag-pinned URL. On **Fedora Asahi Remix / aarch64** the asset
resolved is `dotf_linux_arm64.tar.gz`.

```bash
git clone https://github.com/yandy-r/dotfiles.git ~/.config/dotfiles
cd ~/.config/dotfiles
./bootstrap.sh
```

On Fedora/RHEL the shim itself needs only `curl` and `tar` (both in `@core`), but
release **discovery** — used for private origins and for the prerelease fallback path
that every `-beta` tag takes — needs `gh` or `python3`:

```bash
sudo dnf install -y gh    # or: sudo dnf install -y python3
```
