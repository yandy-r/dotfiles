# v0.2.2-beta

Maintenance release of `dotf` — the native Go provisioning CLI for this dotfiles
repository. There are **no user-facing behavior changes to the `dotf` binary** since
`v0.2.1-beta`. This release adds a **Forgejo-native release pipeline** so the
self-hosted origin publishes its own dotf binaries, alongside the existing GitHub
release.

> **Beta scope.** Unchanged from v0.2.1-beta — `dotf` provisions the real
> daily-driver toolset across the full pass (sysconfig → packages → symlinks →
> firewall). Pin to a tag rather than tracking `latest` if you need stability.

## Highlights

- **Forgejo-native releases.** `.forgejo/workflows/release.yml` now cuts a release on
  the self-hosted Forgejo instance (GoReleaser's `gitea` target in
  `.goreleaser.forgejo.yml`), independently of the GitHub release. GoReleaser is
  installed via `go install` rather than `goreleaser/goreleaser-action`, which is not
  resolvable from Forgejo's `DEFAULT_ACTIONS_URL` (`data.forgejo.org`). The instance
  URL is injected from `github.server_url`, so no hostname is committed to the repo.
- **Clean forge separation.** Forgejo reads `.forgejo/workflows/` in preference to
  `.github/workflows/` (the two are never merged), so all Forgejo behavior — release
  and Go CI — moved there, and the GitHub workflows returned to their original
  marketplace-action form. GitHub keeps cutting the GitHub release; Forgejo cuts its
  own.

## Maintenance

- `ci`: publish dotf releases to the Forgejo instance via `.forgejo/workflows`.

## Install

The GitHub release workflow (GoReleaser) publishes static binaries for **linux,
darwin, and windows** on **amd64 and arm64**, plus `checksums.txt`. The bootstrap
shim resolves `/releases/latest/download/dotf_<os>_<arch>.tar.gz` automatically:

```bash
git clone https://github.com/yandy-r/dotfiles.git ~/.config/dotfiles
cd ~/.config/dotfiles
./bootstrap.sh
```
